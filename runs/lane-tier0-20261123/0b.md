## Part 1 — the clock-mark profiler (`round_clock_us`): diagnosed and pinned, patch 0299 (pure fix, no new switch)

**Symptom** (todo.md:685, continue.md:453): with `TF_DS_CLOCK_MARKS` and graphs on, `round_clock_us.rounds` read
`0xAAAA…` (Zig's undefined fill) and every phase read 0 µs.

**Mechanism (evidence, not speculation):**

- `runs/engine-followup/profile01/frames.jsonl` (pinned image `tensorfold-dsv41:exl3-tp2-234f9080b326`): the raw
  scrape line's clock round counter is `clock_rounds: 12297829382473034411` = `0xAAAAAAAAAAAAAAAA + 1` — the counter
  accumulated `+= 1` per round from **undefined fill**, i.e. `m.clk_rounds = 0` never ran in that build. Same for
  `clk_ph`/`clk_cnt` (they are zeroed in the same three lines).
- With all three counters at `0xAAAA…` origin, every phase's printed us value is
  `clk_ph[tag] / clk_rounds / 1e3 ≈ 0.001 → "0.0"` — **"every phase reads 0 µs" is the same single bug** (division by
  the ~1.2e19 rounds counter), plus the printer rounding to 0.1. `runs/kvreuse-size-20261122/m4-broken/run.log`
  (graphs-on, `TF_DS_CLOCK_MARKS=4`, 2026-11-22) shows exactly that: every phase `[0.0, …]`.
- `runs/w4/e-r1-ctl.rank0.log` (older eager image) has sane `rounds: 1072` and real `wait`/`tail` us — the profiler
  worked before the pinned-image rebuild. The regression window is the image rebuild
  (`zig/src` commit `a149718` "pinned image 234f9080b326: the 117 patches of /opt/tf-patches applied in order"),
  which **dropped the `Model.open` clk-init hunk** (it lives in `zig/patches/0190z-dsv41-build-rank-and-checkpoint-fixes.patch`
  lines 491-493; the worktree has the same lines since its recipe base `0d9f7e3`).
- **In this tree the three `m.clk_*` assignments already exist** (`model.zig:291-293`) and `Round.init` assigns all
  136 Round fields (audited programmatically: zero gaps; `Model.open` assigns every field except `amax_host`/`view`,
  whose defaults are `= undefined`). So the bug is **fixed-but-unpinned** here; the failure mode was a build losing
  the init lines, and the fields' struct defaults are dead code (`m.* = undefined` / `var rd: Round = undefined` +
  field-by-field init — the named bug class) with nothing testing them.

**What 0299 does** (pure fix: no behavior change when the profiler is unused, no new `TF_DS_*` switch needed; it
rides the existing `TF_DS_ROUND_PROFILE` / `TF_DS_CLOCK_MARKS` path, both off by default):

1. **`zig/src/families/dsv41/clock_fold.zig` (new)** — `fold(clk_ph, clk_cnt, clk_rounds, h)`: the round-clock
   buffer fold, extracted verbatim from `Model.verify` into pure host code so it is testable without a GPU.
2. **`zig/src/families/dsv41/model.zig`** — `verify` calls `clock_fold.fold(...)` (behavior-identical: same buffer,
   same `@min(count, cap)` bound, same gap-to-ending-tag attribution, same per-call round count).
3. **Host tests** (the task's required "host test that constructs the profiler state and reads nonzero phases"):
   - "the fold reads nonzero phases from a constructed profiler state" — builds the three accumulators and a
     synthetic `[1 + 2*8]` clock buffer (start/a_in/a_q/tail with known ns gaps over undefined fill 0xAA…), folds two
     rounds, asserts exact per-tag gap sums (3000/800/8000 ns), counts, `clk_rounds == 2`, and the printers'
     per-round us values **1.5 / 0.4 — nonzero phases**.
   - "the fold never reads past the clock count" — a count past the buffer cap is bounded to it; fill after the
     count is never read; one clock alone counts a round with no gaps.
   - "the profile's fields are assigned where the bug class bites" — the 0114-pattern source pin: `Model.open`'s
     body must name `m.clk_ph = / m.clk_cnt = / m.clk_rounds =` and `Round.init`'s body must name all eight clk
     fields (`rd.clk`, `clk_marks`, `clk_shard`, `clk_ratio`, `clk_layers`, `cur_ratio`, `launches`, `launch_mark`).
     A build or refactor that drops any of them fails this test.

## Part 2 — per-round distributions in the scoring pipeline

`runs/overnight-20261122/arms.sh`, `runs/overnight-20261122/table_gpu.py`, `runs/k280/work.py` saved only lifetime
means (one per-round mean per cell in `per_round.tail[0]`/`wait[0]`, one lifetime line in `*.profile.txt`). Changes
(additive only; every existing field and output shape kept byte-identical):

1. **`runs/k280/work.py`** — a sampler thread (`sample_cell`, ~1 s cadence) scrapes the cumulative
   `round_clock_us`/`profile` lines during each decode cell and differences consecutive scrapes into **per-round
   samples**; the cell saves `per_round.samples = {"forward_ms": [...], "pass_ms": [...], "wait_ms": [...]}` beside
   the untouched `per_round` fields. `totals()` gains `_passes`/`_pass_ms_total` (used only by the sampler; `diff()`
   and every saved key unchanged). forward = the GPU clock's stretches a round, wait = GPU idle between stretches a
   round, pass = the drafter pass a pass.
2. **`runs/overnight-20261122/table_gpu.py`** — a new "Per-round distributions" table: per cell × metric
   (forward/pass/wait) per arm, `mean/median/p95/p99` (nearest-rank quantiles) from `per_round.samples`. Cells saved
   before the samples existed (all of k272/k267) show the mean they already carry (`per_round.tail[0]` /
   `wait[0]` µs a round) and `-` for the quantiles — the parenthetical in the task. Note: **this file is untracked in
   the main repo's git** (`git status` shows `??`), which is why git reported "no content diff" at recovery: the
   distribution columns are present at `table_gpu.py:90-113` (verified).
3. **`runs/overnight-20261122/arms.sh`** — beside the unchanged `*.profile.txt` capture, the arm's whole scrape
   series is kept as `*.frames.txt` (`docker logs $C | grep …` — the server restarts per arm, so this is the arm's
   own series) for offline re-scoring. **The pre-existing uncommitted edit is preserved exactly**: the
   `pass_counts|pass_phases_ms` grep widening + its `tail -8` + its comment (this file is ` M` in git with those
   edits still in place; my one addition sits directly under it).
