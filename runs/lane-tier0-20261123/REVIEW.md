## What the window's `probe.py` byte check must confirm before 0206 adoption (task item 3)

On the fresh window image (this tree + re-rolled 0206 with 0298's fix: kernel stores `keys[...] = u ^ 0x8000000000000000ULL`, `tmax[...] = top ^ 0x8000000000000000ULL`; zig `foldKeys` writes `kitKey(x, i)`), comparing the fold's outputs against the kit's `_score_keys` on identical score rows:

1. **`keys`: 0 differing bytes** at every probed column, at widths 64/128/16,384/32,768/65,536 **plus ≥1 width with a partial last 64-key tile** (e.g. 20,000; subject to F2's fault-rule reconciliation). Rows must cover mixed-sign tiles, all-negative (−inf, ties), non-negative (±0 ties, +inf), NaN.
2. **`tmax`: 0 differing bytes at every tile index, including the partial last tile.** This is the decisive check of the flagged INFERRED rule — "the kit's `_score_keys` tmax = the largest kit-encoded key of the tile in the consumer's signed order", which equals `top ^ flip` (top = unsigned max of scoreKey keys). Mixed-sign tiles are the discriminator: an "unsigned max over kitKey" kit rule would pick the negative class's column there and differ byte-wise; so would an unflipped store. **Any differing byte refutes the rule** → re-derive only the `tmax` store (e.g. signed max over kitKey values); the `keys` fix stands regardless (0a open decision 2).
