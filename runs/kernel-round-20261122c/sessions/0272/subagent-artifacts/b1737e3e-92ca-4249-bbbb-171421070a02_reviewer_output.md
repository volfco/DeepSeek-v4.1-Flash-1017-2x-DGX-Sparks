**Findings:**

1. **major — device OOB write via prev cells.** `rdma.zig` `streamOrd` (~line 800) maps up to 8 distinct streams (indices 0..7) but `hdr` is 6 u64 (round + ≤5 cells) and `TfDsTrace.prev` is documented `[4]` (ring_trace_rec.cuh:9). `tf_tr_claim`/`tf_tr_done` index `t.prev[t.stream]` (ring_trace_rec.cuh:60/96) — streams 5..7 write past the 48-byte hdr allocation. Not reachable at the served shape ("up to four streams"), but the map's own comment sanctions 8. Fix: cap the map at 4 (`streams: [4]`, `nstreams < 4`) to match the cells, or allocate `9*8` and fix the `[4]` doc.
2. **major — `proxyRec` never resets a claimed record** (rdma.zig:826-835). Unlike `tf_tr_claim` (zeroes all fields, seq last), the proxy claim leaves `last_post/parts/flag/flags` stale from the slot's previous record. After wrap (4096·n sequences — routine in long runs), records missing an event (batched-arrival members' `parts`, aborted exchanges) carry stale timestamps, and `rec.flags |= 1` (woke) is sticky — every later record in a woken slot reports woke=1. Fix: zero the record in `proxyRec` before the event writes.
3. **major — proxy part/flag metric degenerate** (rdma.zig:563-568). `parts[d]` is stamped only for `q == got.to` and with the *same* `t` as `rec.flag`, so `proxyTimes.completion_flag` is 0 for those records and null/stale for the rest; the non-triggering NICs' completion observations are dropped entirely (Arrivals saw them in earlier polls). The brief requires "each NIC part's receive completion observed" and a "last-completion→flag" summary. Small fix: stamp `parts[d] = t` for every q in `got.from..got.to` and take a fresh clock read for `rec.flag`; or `shortcut:`-comment the limitation and drop the metric.
4. **minor — TP4 (`two`/ring2d) path untagged and untraced.** ring2d.zig:91/100/107 pass `.{}` keys, and `ring2d.Rings.open` callers (model.zig:478, layer_main.zig:422) never set `trace_n` — in the 4-node 2D split the switch silently does nothing and all hidden gathers would be `other` even if wired. Fine if TF_DS_RING_TRACE is scoped to TP2 (the served config), but the report should say so and the code needs a `shortcut:` note.
5. **minor — hidden per-round host sync when on.** `traceTick`'s `cuMemcpyHtoDAsync_v2` from pageable `&tr.tick_host` (rdma.zig:840) performs a stream sync before the copy per CUDA pageable-async semantics — outside capture and not per-gather (contract holds) but it perturbs round timing invisibly. Upload from a pinned staging cell or document.
6. **nit — comment mismatch:** ring_trace_rec.cuh:8 says the arg is "all zeros when the trace is off"; `traceArg` returns `.{}` whose `layer` default is −1. Harmless (kernel checks `recs`), fix the comment or return explicit zeros.
7. **nit — missing `shortcut:` comment** for the known side-stream limit (sendRows' stage on `ss`, recvRows' collect elsewhere leaves `prev[ord(ss)]` stale); only the >8-streams limit is commented.
8. **nit —** all sequences processed in one proxy wake share one `t_ring` doorbell-observed timestamp (rdma.zig:518).

**Risk 3 wraparound/clobber (device ring): clean** beyond findings 1-2 — helpers are sampled-only, slots are disjoint per sample, identity-last claims are read only after the stream syncs + synchronous download, drops counted as expected−kept.

**Merge verdict: BLOCK** — findings 1-3 must be fixed (1 is memory-unsafe past 4 streams; 2-3 corrupt the records the feature exists to produce).
