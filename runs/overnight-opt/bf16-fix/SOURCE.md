## Bulk dispatch failure

The two standalone entry points now parse the option. `Model.open` enables it before chunk allocation on both ordinary TP2 ranks. In each prompt layer `prompt.attention` projects each rank’s four groups of width 1,024 to the model’s 5,120 hidden channels. The quantized projection `wo_b` therefore has K=4,096 and N=5,120 on both ranks. Through 128 rows per chunk, the default `mmRows` uses grouped EXL3 with a BF16 output descriptor. At 129 rows it switches to `exl3_prefill.matmul`, whose Triton `_gemm` dispatch includes both shape constants and the `OUT` pointer type. This boundary applies to rows actually computed in the chunk, including after a cache cut. [Follower option](../odds-ranks.patch) · [Original partial and gather change](../../combo4/pulled/0185-dsv41-tf-ds-bf16-partials-off-by-default-lossy-r.patch)

The actual `abe07c7d` kit manifest contains 198 kernels, including nine `_gemm` variants. The only K=4,096/N=5,120 entry takes `OUT: *fp32` (`f87b98fc4790a41d348c74fc9dcc7468c3612cee5fcec016083ebc3dfd01fa2c`). The exact and fallback selectors both require a matching pointer element type. A CPU-only ReleaseSafe fixture ran the engine’s `tri_markov.matmul` wrapper and `cuda.aot.specsHave` against the installed manifest. At 129, 131, 1,024 and 2,048 rows it resolved FP32 and rejected direct BF16 every time. Either rank reaching this bulk projection on the original build must return `MissingTritonVariant` before its attention gather. A rank-side reproduction could confirm the first emitted backend error of the failed 3K request. ## Buffer and transport contract

The optional local BF16 output `pb` is contiguous `[rows, 5120]`. The NCCL all-gather sends `rows × 5120` BF16 elements per rank and packs its result in rank order into `gb`. The feed-forward mix widens `world × rows × 5120` BF16 values into the existing FP32 `ga` on the same stream before it sums the rank partials. The optional 2,048-row `pb` and `gb` allocations add 20 and 40 MiB per rank. A full layer’s send contribution falls from 40 to 20 MiB per rank. The MoE gather and decode-round attention projection and gather continue to use FP32. The shared fix therefore targets prompt processing. [Pinned port and paths](../../combo4/pulled/0185-dsv41-tf-ds-bf16-partials-off-by-default-lossy-r.patch)

The isolated fallback leaves the short grouped EXL3 and plain-weight projections writing BF16 directly. For a quantized bulk prompt it writes the kit’s supported FP32 projection into the preallocated `pa`, then launches the existing same-stream `tf_f32_to_bf16_kernel`, which uses `__float2bfloat16_rn`, into `pb`. The same BF16 gather and widen follow. Per 2,048-row layer this conversion reads 40 MiB and writes 20 MiB locally. Its exposed cost and the net gain from the reduced wire payload require the serving comparison. [Candidate patch](fallback.patch) · [Package and executable hashes](package.json) · [Source and archive proof](proof.json)

Both candidate executables target AArch64 and preserve all embedded CUDA modules from the rank-corrected odds build, 20 in the native executable and six in the standalone follower. The archive’s Dockerfile overlays those two executables on `tensorfold-dsv41:exl3-tp2-234f9080b326` and requires no network. The score-first replay has 40 frozen examples from 20 source groups. Their prompt lengths span 291–566 tokens, so a cold score enters the bulk path. Serving acceptance still needs completed replies, source-paired NLL, and measured wall time at matched prompt depth and cache state. In the archived November 13 external cohort, all 652 completed requests had more than 128 reported uncached prompt tokens, including all 629 with a positive cache cut. The smallest residual was 171 tokens and the median was 2,159.5. These totals make bulk prompt processing relevant to the observed workload even under heavy cache reuse. A direct-output implementation would require one additional `_gemm` specialization. The deployed kit has a BF16-output K=4,096/N=1,024 template whose runtime argument types and alignment requirements match the desired signature. Only its N constant changes to 5,120. The kit builder accepted the one-variant spec in dry-run mode. Building would require the matching Triton/compiler image, reproduction of the template hash, and separate correctness and timing tests on a private kit. ## Precision agreement and persistent cache compatibility

The rank-corrected odds build sets the effective BF16 option in `Model.open`, yet its initial `lanes.pairSwitches` check compares only exact-resume and speculative-sampling bits. Its full rank/spill fingerprint also omits prompt precision. With identical image, kit and other settings, unlike ranks can reach an attention gather with incompatible NCCL element types. When both ranks change mode together against existing spill directories, they can look up checkpoints produced with the other precision. The benchmark uses one checked mode on both ranks and separate spill directories for the two arms. No mixed-precision restore or mismatched NCCL call was attempted on hardware. [Source change and affected paths](compat.patch) · [Serving arm configuration](../engineering02/bf16-partials/armed.json)

A separate optional correction adds the effective BF16 mode to the initial pair-switch frame and to the persisted common feature string only when enabled. The original and corrected binaries were compared on the host using the real rank-wire leader, follower, feature serialization and sharded-store compatibility digest. The fixture fixed all other inputs and ran both mixed-rank orderings, FP32/FP32, and BF16/BF16. Original code accepted all four combinations and gave each rank the same spill key across precisions. With the correction, both mixed pairs rejected the hello with `FingerprintMismatch` on field `features`; the leader blocked a follow-up write. Both homogeneous pairs agreed. Corrected FP32 retained the original common digest and both rank-local store keys byte for byte. The two BF16 store keys differed from their FP32 counterparts. A separate test exercised the initial switch bits under all four settings of exact resume and speculative sampling. The active BF16 benchmark binaries omit this compatibility correction.
