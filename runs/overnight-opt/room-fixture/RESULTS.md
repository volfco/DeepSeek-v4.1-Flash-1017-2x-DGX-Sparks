# Optimized fake stream finished before the restore retry

Both one-piece and chunked prompt variants failed the same prerequisite in the original ReleaseSafe host seam tests. The fake decoder finished its 100,000-token budget before its second refusal. In each failed case the host counted one room wait, resumed the waiter at its exact eight-token durable cut when the lead ended, and committed one disk hit. The expiry count remained zero. [Original failures](original-safe.log) · [Fixture observations](diagnostic.patch)

The first refusal in a timestamped chunked run was visible 1.053 ms after submission, and the lead finished at 896.939 ms. The scheduler's retry is due after one second while the lead holds the room. In the same run the one-piece variant reached the retry with 99,969 tokens and passed. This timing difference explains why an optimized host can fail a test that passes on a slower host. [Timestamped reproduction](original-timing.log)

The correction sets the fake lead's token limit to the maximum representable request budget and cancels it immediately after observing two refusals. Stream history grows with emitted tokens. Fake refusal settings and its durable point are installed before either request, and a failed assertion cancels and drains each submitted request before releasing its sink. Checks of the actual retry, cancellation, exact tokens, cached cut, completed restore, and final queue state remain in place. The patch changes only the unit test. [Corrective patch](../room-fixture.patch) · [Reproduction from a clean engine checkout](check.sh)

Both clean 0125 and 0127 source trees passed all 143 engine API tests with both the test module and lane module explicitly compiled in ReleaseSafe, and again with both modules compiled in Debug. Ten consecutive focused ReleaseSafe runs passed both corrected variants. These checks cover the engine API test target. The repository's complete host suite also contains independent targets.
