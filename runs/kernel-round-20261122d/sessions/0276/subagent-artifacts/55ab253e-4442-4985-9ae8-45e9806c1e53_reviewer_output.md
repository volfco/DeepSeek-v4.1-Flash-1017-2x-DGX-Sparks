1. **minor** — `zig/src/native/cuda.zig:487-498`: with `TF_DS_CACHE_REPLACE_STALE=1` but no spill tier and no `TF_DS_EXACT_RESUME`, `usable` is never copied into `snap_vt` (gated on `rules.exact` at :490 and on `loaded.tier` at :496), so the arm is silently inert in that configuration — even though `native.zig:449` supplies `sn.usable` (incl. for endstate-only runs). This is the source patch's "usable half", deliberately out of scope per the brief and already listed in report-0276's "Known gaps"; both served shapes (lanes_main always wires `usable`; production runs `SPILL_GIB=180`) are covered. Smallest fix if ever wanted: also assign `h.snap_vt.usable = sn.usable` when `replace_stale` is on.
2. **nit** — `zig/src/core/prompt_cache.zig:1158` + `:1218-1220`: a replacement drops the old entry's sticky `shared`/`group` (refresh does `e.shared = e.shared or shared` and keeps a non-zero `e.group`; the fresh entry gets only the current keep's flags). Policy nuance (shared placement priority / tier share can be lost when a shared cut is re-kept unflagged); brief is silent and harness/model match the implemented semantics.
3. **nit** — `prompt_cache.zig:1155-1172`: if the fresh save after a replacement is refused (budget / restores in flight), the keep returns `false` (counted `refused`) after having changed the cache. The removed copy was dead, so nothing valid is lost; same as the source patch. A `shortcut:`-style comment or a test for this path would document it.
4. **nit (analysis caveat, item 3)** — `zig/src/families/dsv41/lanes_main.zig:80-85`: unlike `lane_host`'s kept→reported() ordering, `keepHook` keeps `j.entry` live across its own `keepWith`, and the endstate end keep (`lanes.zig:1154`, `at = done.len`, **not** mark-gated) can duplicate the resumed entry in the identical-resend corner (a `full_end` entry at `prompt.len` resumed with zero rows). Verified safe in practice: the arm there needs the state stale (dead at its own length — the resume is already doomed), `keepHook` reads `j.entry` before `keepWith`, the end keep is the final hook call, and `st.resumed` (`lanes_main.zig:409`) only compares the pointer. So "a replaced entry cannot be *validly* in use" holds; the stronger wording "cannot be in use" is true only for `lane_host`'s `Job.entry`, and cross-job frees are no broader than `victimBut`/`reserve`/`full_end`/`adopt` today.
