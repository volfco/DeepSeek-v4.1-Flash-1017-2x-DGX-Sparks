## Premise correction (read this first)

The item claimed the clamp is "bit-exact by construction ... (causal attention, independent MoE)". **The drafter
block attention is NON-CAUSAL.** Every block row attends every block row of its stream, including future rows:

- `draft.zig:695` — the pick fill `for (0..n) |k| hb[r * bw + k] = i * n + k`: row `j`'s sparse-attention pick
  list includes ALL `n` block rows of its stream, `k > j` included.
- `draft.zig:912` — the port's own comment: "each row sees its stream's 128 newest absorbed positions (to q0 -
  1) and every block row of its stream".
- `tri_attn.sparseAttn` applies no causal mask to the comp picks; in prefill the comp entries' causality is
  host-made via `vis` (`prompt.zig:1120`: "the compressed entries row i may see (host-made: the same integers)").
- Upstream reference (read-only, `~/Workspace/vllm-reference-src`):
  `vllm/models/deepseek_v4/nvidia/dspark.py:8-9` — "To implement non-causal attention, we leverage the sparse
  attention implementation to include the future query tokens in the top-k indices for each query token";
  `vllm/model_executor/models/qwen3_dspark.py:5-6` — "DSpark drafts a whole block in one parallel pass
  (DFlash-style: context-KV precompute + **a non-causal query-block forward**)".

**Consequence:** rows >= `steps` feed rows < `steps` through every stage's intra-block attention (a row's
stage-j key comes from its full stage-<j hidden state), so clamping the pass to `N * steps` rows changes the
scored rows' logits, `dr.drafts` and `dr.confs`. No bit-exact stage-row clamp exists. The item's byte-compare
gate (drafts/confidences/rings) would have failed, and the "rows past steps change nothing (causal attention)"
note would have documented a false claim.

What *is* true: the Markov loop reads only block rows `0..steps-1` per stream (`tri_markov.zig:128-145`, step
`i` scores `local` row `i` per stream, `stepsCut` runs `count = steps` at `:172-186`), the confidence head reads
only `steps` rows per stream (`draft.zig` body's conf section: `confPack`'s `steps` arg / the else-chain's
`toF32(..., steps * d)`), and `holdDrafts` (`lanes.zig:2215-2222`) marks drafts past `steps` `no_chance` — so
the *readers* only consume the scored rows. The un-scored rows still *influence* the scored rows.

## Open decision (operator-declined 2026-11-23): option B, the full stage-row clamp

- **Mechanism:** `blockRows` (`draft.zig:663-666`) returns `@max(dr.n, steps)`; `pass()` runs every stage on
  `R = N * n` rows; rows >= `steps` per stream are computed stage by stage and read by nothing. Clamping the
  stages to `N * steps` rows would save that compute (the item's ~1.2 ms a four-stream round / ~5 ms an
  eight-stream round ceiling, `runs/trace-review-20261123/out/pass_x4.txt`).
- **Why declined (evidence above):** non-causal intra-block attention; the clamp changes drafts and
  confidences. Per the operator ruling: safe subset only, no B code in any form.
- **Gate would have to move:** from byte-comparing drafts/confidences/rings to a reply-hash / verify-token
  comparison (drafts may differ; the verify decides which drafts land, so reply bits stay — the
  `TF_DS_DRAFT_BLOCK` precedent at `draft.zig:59-64`: "a reply keeps its bits either way"). That is an item
  contract change, hence an operator decision, not a lane decision.
- **Draft-depth concurrency caveat (the repo already records it for pins):** draft depth is normally the
  concurrency rule's (`depth()`, `draft.zig:986-993`, by = (5, 5, 3, 3) live streams at 16-row rounds); the
  benchmark pins override it (`lanes.zig:421-441` "at most one may be on", `lanes.zig:699` "a benchmark pin of
  every head draft's depth (null: the rule decides)"). Under B, drafts would change at every pin and every
  stream count, so no pinned-depth or concurrent arm could keep a draft byte-compare — only reply hashes.

## Delta against 0265: none (C fully covered)

Option C (as approved): keep the backbone stages on `N * n` rows; clamp the vocabulary-head and
confidence-pack inputs to the first `steps` rows per stream. 0265's diff (`git show c04f020 --
zig/src/families/dsv41/draft.zig`):

1. **Vocabulary head: covered.** The on path runs per-stream `_collapse` at the scored rows, one `_rmsnorm` over
   `N * steps` rows and the head `prompt.grouped` at `M = N * steps`, packed rows `i * steps + s` in the same
   `dr.xc`/`dr.xn`/`dr.local` buffers (the pre-norm `xc` rows are retained for the confidence head).
2. **Confidence-pack input rows: already scored-only, before and after; nothing to clamp.** The confidence path
   never computes un-scored rows: `confPack` processes `N * steps` rows (`n` is stride-only,
   `conf_pack.zig:156`: "n: the block rows (>= steps)" as the xc row stride), the else-chain reads `steps` rows
   per stream, `gatherRows`/`toF32(embs)`/`copyRows`/`blas.xv` all run `N * steps` rows. 0265 threads the
   stride: `confPack`'s `n` arg becomes `lrow` (`steps` packed / `n` full) and the else-chain's `toF32`
   offsets follow.
3. **Engagement (`steps <= 4`): mechanical, nothing to widen.** 0265 engages iff `steps < n`; with
   `n = blockRows(steps) = @max(5, steps)` that is exactly `steps <= 4`. At `steps >= 5` there are no
   un-scored rows (`n = steps`), so no wider engagement exists. At `steps == n` the full arm runs unchanged.
4. **The SpecTap stride trap is handled by 0265** (see below).

## Stride trap (carried as far as the clamp requires)

`SpecTap` (`draft.zig:182-183`) strides the local logits and `sq` with `dr.n` where `NoiseTap` (`draft.zig:163`)
uses `dr.bn`; `tri_markov.localBestCut` strides with the caller's `block` (`tri_markov.zig:133` `l_seg`,
`:139` `l_row = block * lw`, called with `dr.bn` from `body`). Today this is safe only because spec and
`TF_DS_DRAFT_BLOCK` refuse to combine (`draft.zig:392-394`). Any future clamp of the block rows (or 0265's
packing) must follow one row stride: 0265 already threads `rs`/`lrow` through both taps (`SpecTap.rs =
dr.n` explicitly on the off path for identity, `sq`'s stride unchanged by design — lanes' spec gather reads
`stream * n + step`). Nothing further needed here.
