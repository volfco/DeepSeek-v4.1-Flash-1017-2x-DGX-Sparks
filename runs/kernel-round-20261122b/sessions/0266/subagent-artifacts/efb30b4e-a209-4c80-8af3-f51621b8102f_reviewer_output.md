## Review — kernel patch 0266 (`TF_DS_COMPRESS2_PAIR_ONCE`)

Scope reviewed: worktree diff vs base (`zig/kernels/cuda/dsv41_torch.cu`, `zig/src/families/dsv41/{dsv41,exact,fused_trace,round}.zig`) plus the untracked `zig/src/families/dsv41/compress2_pair.zig`, against BRIEF-0266. Also inspected the h0266 harness artifacts in the runs dir as evidence. No files modified.

### Findings

1. **fine — Off-path identity (contract 1).** `zig/kernels/cuda/dsv41_torch.cu:680-797` is a purely additive hunk (+117/−0); no existing kernel line changed. `round.zig:1088-1095` keeps the old `compress2xNorm` call verbatim in the else arm, gated on `e.exact.compress2_pair_once and compress2_pair.works(true, R, hd)` (false when unset: `exact.zig:72` → `compress2_pair.zig:18` `parse(null)`→false). Pair kernels are looked up only when on (`exact.zig:86-87`). No new launches, transfers, or output bytes when unset.

2. **fine — On-path arithmetic identity (contract 2).** Pair body `dsv41_torch.cu:743-769` mirrors `tf_ds_compress2x_norm_body` (`dsv41_torch.cu:630-656`) instruction for instruction: same `tf_ds_compress2_pair` inputs, same bf16 round → `x`, same D==512 `row[]` staging, same `squares4`/`warp_sum` order, same `__fadd_rn(__fadd_rn(w0,w2), __fadd_rn(w1,w3))` fold, same `inverse_rms`, `__fmul_rn(x, inv)`, and final `__fmul_rn(wv, y)` + round. Only delta: the once-rounded `yv` (`:769-772`) is stored to every matching row instead of recomputed per row — same bytes, one rounding, identical to the off path's per-row rounding.

3. **fine — (a) Equal keys ⇒ identical outputs; no read-before-write.** Case analysis on `tf_ds_compress2_partners` (`dsv41_torch.cu:538-553`) + resolution (`:726-742`): (i) every row resolving a key gets the same `r*` = first row with `rslot == q` (the `rows == 1` shortcut can't split duplicates — G=1 has unique keys); (ii) the `row == g` arm reads `own_kv = ckv[g*ckv_ld+tid]` — the same memory the other duplicate reads via the `row >= 0` arm (`ckv[r**ckv_ld+tid]`); (iii) the ring arm is taken only when no row's `rslot` equals `q`, and scatters write only `rslot[g]` slots (`:717-718`), so a same-launch writer can never race the ring read; (iv) `ok0/ok1`, `w[tid]`, `ldo`, `eps` are key/shape-constant. The mirrored case `own(g1)==q0, own(g2)==q1` (e.g., window at 62..63) resolves to `(ckv[g1], ckv[g2])` in both rows. Ring wrap at raw=64 and positions differing by 64 cannot co-occur in one round (one stream's round rows are consecutive positions — `round.zig:92-94` — with `max_rows` 48 < `raw_rows` 64 — `round.zig:46,949-950`); even if they did, the resulting scatter race is identical in both paths (pre-existing, not diff-caused). Duplicates never read any staged result at all (each out row has exactly one writer, its key's first block; no cross-block reads), so the ordering constraint is satisfied trivially.

4. **fine — (contract 3) Pair key rule.** `setGlue`'s `gi = slot*raw + @mod(groups*2+[0,1], raw)` (`round.zig:950-953`) matches `compress2_pair.pairKey` (`compress2_pair.zig:32-38`) exactly, and the slot base separates requests (also unit-tested: "rows of different requests never share a pair").

5. **fine — (b) Ballot scan.** `tf_ds_compress2_first_pair` (`dsv41_torch.cu:695-703`): `rows`, `q0`, `q1` are block-uniform; each warp evaluates the identical predicate set (`r = first + (threadIdx.x & 31)`, warp id masked out), so `m` is identical across warps and uniform within each warp — `if (m) return` is block-uniform, and no ballot follows a divergence. Mask `0xffffffff` is valid (blockDim 128/512 = whole warps, enforced by `works()`). Row `g` always satisfies its own key predicate (`q0/q1` loaded from `gi[2g]` at `:714`), so the return is never −1 for the caller. Independent evidence: the harness's `__ballot_sync` emulation synchronizes 32 lanes per warp with barriers (`harness.cpp:83-88`) and would deadlock on non-uniform participation; it completed 170/170 cases.

6. **fine — (c) Early return skips nothing observable.** `dsv41_torch.cu:720` returns after the raw-ring scatter (`:717-718`, identical to off path `:606-607`); the broadcast (`:771-772`) writes every matching row's `out` row (address-identical to the off path's `out[g*ldo+tid]`); the skipped `atomicExch(invalid, 1u)` (`:723` vs off path `:610`) is idempotent and performed by the key's first row (`ok0/ok1` are functions of the key), so the flag's final byte is identical — and the harness byte-compares it in all cases (`harness.cpp:394,398`).

7. **fine — (contract 4) Switch.** `compress2_pair.zig:15-28`: null/""/"0" off, "1" on, anything else stderr + refusal; `fromText` error aborts `Exact.load` (`exact.zig:72`) before any launch, identically on both ranks. Kernel lookup gated on the switch (`exact.zig:86-87`); call site falls back to 0197's kernel when off or shape unsupported (`round.zig:1089-1095`). Note it is deliberately stricter than the house `ops.onValue` (`ops.zig:61-64`, garbage→off) — required by the contract, so fine.

8. **fine — (contract 5) Graph safety / ranks.** `compress2xNormPair` (`exact.zig:245-268`) is `compress2xNorm`'s arg list verbatim (`:215-237`), same grid/block/pdl split (macro at `dsv41_torch.cu:775-794` mirrors 0197's, weight preload before `pdl_wait` kept), no syncs or pageable transfers; no rank-conditional code in the diff over replicated glue.

9. **should-fix (test gap) — G > 32 is never exercised.** The largest h0266 case is `mixed 4x7` = 28 rows (`harness.cpp:449-476`; single-stream windows ≤ 7), so `tf_ds_compress2_first_pair`'s second ballot chunk (`first += 32`, offset return at `dsv41_torch.cu:699`) and the multi-chunk `tf_ds_compress2_partners` path run only in production, where R reaches 48 (`round.zig:46`) with live duplicate keys at rows 32+ (e.g., R=48 start=0 → duplicates at 32/33…46/47). The formula is correct by inspection (matches the proven 0197 pattern) and the Zig tests are host-side key-rule only, so this is coverage, not a known bug. Smallest fix: one harness case with a 33–48-row single stream at even and odd starts.

10. **nit — Gate duplication.** `exact.zig:247` gates on `compress2_pair.works(true, g, d)` while the neighboring `compress2xNorm` uses the single-source `fused_trace.compressArm` gate (`exact.zig:217`). `works()` is `decodeOk(true, …)` verbatim today (`compress2_norm.zig:38-40` vs `compress2_pair.zig:30-32`) — identical behavior, but the two can drift. Smallest fix: delegate `works` to `compress2_norm.decodeOk`.

11. **nit — Third copy of the gi/rslot rule.** `harness.cpp:200` duplicates `setGlue` (`round.zig:949-953`) and `pairKey` (`compress2_pair.zig:32-38`). All three agree today (checked pairwise), but no test cross-checks them; drift would silently invalidate the byte-compare evidence. A small test computing `setGlue`'s gi for a few `(p, slot, raw)` triples against `pairKey` closes it.

12. **nit — `distinctPairs` fixed buffer.** `compress2_pair.zig:48` `keys: [64][2]i64` OOB-writes if called with `raw > 128` (>64 distinct keys). Safe for raw=64 (≤32 keys/stream) and test-only; an `assert(n < keys.len)` would make the limit explicit.

### Verdict: **safe to commit** (OK with notes)

No blockers; all five contract items and all four scrutiny questions check out from source and harness evidence. The one should-fix is a harness coverage gap (G > 32 ballot chunk), which matters before turning the switch on in production — the switch being off by default keeps it non-blocking.
