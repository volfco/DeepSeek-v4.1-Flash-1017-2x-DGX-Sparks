# Fused kernel benchmark audit through image 2bb052f

**Benchmark 0261 first.** The serving gate timed greedy rounds, while the selector runs on eligible sampled rounds. The selector also has eight unconditional radix passes over 64,640 logits per rank. Two smaller experiments have identifiable work to remove on the served path: reuse the verify round's position and ring-slot buffers in 0269, and select the split query path for 128-row prompt indexers in 0198. The other losses below merit narrower diagnostics or have already been overtaken by a better implementation. This review used the saved runs and engine source. The only new execution result is the CPU selection check below.

## First hardware window

### 0261 · Sampled verification top-k

1. `lanes.zig:1455–1474` selects the device-draw path and the round's largest eligible k. Greedy-only, host-logit and speculative host-draw rounds bypass it. `round.zig:2184–2193` puts local selection directly before the two-rank gather. At k=20 the exchange is 160 bytes per row per rank, down from 258,560. The original speed workload bypassed the switch. The separate sampled panel compared seeds, hashes and lengths. A later banner proved engagement. [Gate](../runs/overnight-20261122/k260-gate/RESULTS.md) · [Lineage check](../runs/overnight-20261122/lineage/RESULTS.md)
2. `dsv41_ops.cu:1670–1705` assigns one 1,024-thread CTA per row. Each of eight digits scans every logit, even when the selected histogram bin completes the remaining quota exactly. Thread zero searches up to 256 bins. Lines 1709–1723 scan again to collect and rank the winners. That is nine logical reads of each row, about 2.22 MiB per row per rank before the selected values are reread. This is a count of load requests in the algorithm. Cache hits can reduce external traffic. [0261 implementation](../zig/patches/0261-dsv41-tf-ds-topk-merge-off-by-default-sampled-ve.patch)
3. **Test the complete-bin exit first.** After consuming the bins above the cutoff, break uniformly when the remaining rank equals the cutoff bin's population. The prefix with the remaining low bits zero is then an inclusive threshold selecting exactly k unique keys. The existing 0254 selector already implements the warp histogram search and this stopping condition at `dsv41_ops.cu:183–219`. Keep 0261's own `tf_ds_draw_key`, global IDs, raw output value bits, ordering and rank-0 first-column NaN flag. The indexer's score-key encoding and output order differ. In particular, a rank-1 ID range starting at 64,640 straddles 65,536, so copying 0254's local-column high-byte shortcut verbatim would break ties. [0254 implementation](../zig/patches/0254-dsv41-stop-score-top-k-at-a-complete-radix-bin-u.patch)
4. **CPU check in this audit.** Compared the inclusive cutoff's complete set of sorted keys with a full descending sort for 64,640 columns at global offsets 0 and 64,640, with k=1, 5, 20 and 56. All 32 comparisons matched. One seeded Gaussian FP32 row stopped at digit two for all eight rank/k combinations. A four-valued row and an all-NaN row took eight digits throughout. Rows mixing infinities, signed zeros and NaNs took seven or eight. This checks the stopping rule. Serving-logit pass counts and GPU latency are open.
5. `model.zig:1915–1917` and `dsv41_ops.cu:1731–1775` materialize the two-list merge and immediately reload it for the draw. A second, separately timed variant could merge the two short sorted lists into the draw CTA's shared memory. Preserve the FP64 probability accumulation order, the mixed greedy-row rule and the seeded draw. Start with selector-only timing so this second change can be attributed. [Kernel contract and CPU tests](../runs/kernel-round-20261122/report-0261.md)

Use three arms on one candidate image: full-logit fallback, shipped 0261 and early-exit 0261. First measure local select and select-through-draw. Then time long seeded sampled requests at one and four streams with k=20, plus mixed k up to 56. Record effective path and rounds. Exercise k=0, −1 and >56 through the API to verify normalization/fallback and compare seeded output with control. Report sampled tok/s and chunk-gap p95. The greedy exact panel checks regressions elsewhere.

### 0269 · Reuse all three contiguous inputs to drafter absorb

At `5d1b4cd`, `model.zig:1773–1779` walks the selected verify windows in order. `draft.zig:522–534` checks their tap spans and elides one copy per contiguous item. Lines 535–544 still rebuild the positions and ring indices on the CPU and enqueue **two host-to-device uploads on every nonempty absorb**. Lines 545–554 pass the direct taps and those freshly uploaded arrays into the projection and per-stage ring writers. The tested switch already removed the tap copies and showed −0.05% client tok/s. [Source audit](../runs/kernel-round-20261122c/report-0269.md) · [Measured result](../runs/overnight-20261122/k269/RESULTS.md)

There is an existing producer for both arrays. `lanes.zig:207–216` sets positions to `start + j` and records the same slot for every row of the window. `round.zig:923–939,964–976` uploads those positions as `rd.pos` and sets the `.wslot` plane to `slot * ring_size + pos % ring_size`. The drafter pool and target both use `window + 16` on this tree. For a contiguous interval beginning at verify row j, pass views offset by j elements to the absorb ring writers. Guard those position and ring-layout assumptions and keep the views alive through the last read on the engine stream. The packed path handles gaps or different position layouts. This experiment saves the two uploads in addition to the tap copies and avoids a new GPU launch. Compare the existing direct-taps arm against the three-view arm, including multi-window, nonzero-first-row, wrap and gapped cases. Time the complete eager absorb and profile-off client decode. The profiler can force a synchronization at `model.zig:1781–1785`.

### 0198 · Dispatch the 128-row prompt query separately

`prompt.zig:506–507` allocates one `ch.iq` and one `ch.iq4` per chunk scratch object. At lines 1514–1522 the projection refreshes the input, then either the fused query or the in-place kit RoPE plus FP4 consumes those same buffers. The eight-distinct-buffer graph in the old experiment does not model that address pattern. Intervening layers can still evict the buffers. The isolated split won by a paired 2.56–3.30 µs, the eight-use same-buffer control favored split by 1.07–1.08 µs, and eight distinct buffers favored fusion by 0.98–1.14 µs. The same-buffer control used identity RoPE so that repeatedly rotating in place was valid. [Recorded graph experiments](../runs/suite-fused-next2-20261121/query128/RESULTS.md)

Try a **prompt-only, exactly-128-row** dispatch override. Compare current fusion with the existing split using the same scratch addresses, real RoPE, fresh projection and representative intervening work. Compare downstream query bytes. Count executions and multiply the measured saving by calls per prompt before scheduling a cold-prefill suite. The 48- and 1,024-row evidence favors fusion. The FP4 conversion-intrinsic variant was already slower on the pinned `sm_121` target. [Geometry and instruction experiments](../runs/fused-next-20261121/wp3/RESULTS.md)

There is also a source-level variant if the fused query itself needs to improve. In `dsv41_torch.cu:979–990`, the pair kernel still takes a **half-warp masked** integer maximum. The earlier 0.10 µs penalty for masked reduction was measured on the latent kernel. The handoff's whole-warp observation does not cover this pair variant. Compare the current reduction with four width-16 shuffle/XOR maximum stages over the same sign-cleared integer bits, with the rest of the kernel identical. Check scale and output bytes at NaN, signed zero and rounding boundaries. Test 48/128/1,024 rows to protect the shapes where fusion wins. [Pair kernel source](../zig/patches/0241-dsv41-the-decode-query-s-geometry-follows-the-ro.patch) · [Prior reduction measurements](../runs/fused-next-20261121/wp3/RESULTS.md)
